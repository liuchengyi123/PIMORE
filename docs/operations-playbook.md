## 0. 一句话结论

## 3. 「拼单」拆解：你说的到底是哪种

### A. 一人凑满（满减 + 包邮 + 券）—— 现有能力已完整
生死线凑单率 ≥60% 的杠杆（运营动作，全可用现有功能做）：
1. **组合设计**：同品类「主推 + 补款品」配对（bundle 弹层已能放同品类网格），让「差 $2.6 包邮」时永远有恰好补上的品。
2. **结算页 addons 精选**：只放「差多少能触发下一档优惠」的品，不放无关品（app.py:1894-1910 已是 addons 位，选品要克制）。
3. **差 X 送券弹窗**（V2 P1-1）：把「再买 $3 省 $4」换成券的面额刺激。
4. **挽留邮件**（V2 B4/P1-3）：弃购 1h/24h 两封。
5. **数据监控**（V2 B5）：凑单率按周看，低于 60% 先调券面额，再调组合。

### B. 多人拼团（Temu 式 social group buy）—— 代码里没有，另一个产品决策
- 现状：无 group 表/成团逻辑/团长优惠。
- 要不要做：你的客单价（$7.8-25）低 + 国内直发，拼团裂变价值高；但成团时限、虚拟成团、团长免单这些机制是完整功能开发，且会加重履约复杂度。
- 建议：**先做 A 跑 4-6 周凑单率数据**；如果 60% 达标且流量有富余，再立项 B（可参考 V2 P2-3 的「组合包」先做最简版：2 件 95 折，而不是真拼团）。

## 4. 最大机制缺口：渠道追踪（决定投流 ROI 能不能算）

**事实**：visits 表字段是 day/kind/sku/country/lang/visitor/cents/qty（db.py:237-249），**没有 utm_source/referrer 字段**。ops.board 的漏斗分国家/语言/商品，但不分渠道。

**后果**：你说「自然流 + 小额加热 + 复购摊 CAC」——这个模型的前提是按渠道算 CAC 和凑单率，现在算不了。同一笔加热花出去，不知道带来的是访客还是买家。

**解法（暂缓至投流启动前）**：
- 现在**不做代码改动**：连连未接通，加热进来的人下了单也付不了款，渠道成本算出来也是亏。
- 投流前：链接自带参数（`?utm_source=...`）+ 用表格记录几天即可（粗糙但够用）。
- 真正开始投流时：再并进 V2 B5（visits 加 referrer 字段 + /admin/stats 按渠道切片，约 20 行）。

## 6. UI 评估（丑不丑，怎么改）

### 6.1 总体判断：不算丑，是「完成度很高的功能电商模板感」

| 维度 | 评分 | 依据 |
|---|---|---|
| 结构/组件完整性 | 8.5/10 | 底部弹层、SKU 规格选层、购物车粘性摘要、三档响应式（720/1100/1400）、触控 44px、safe-area、tabbar |
| 移动端适配 | 9/10 | 2→4→5→6 列商品格、底部 buy-actions 悬浮、搜索全宽、PWA 引导 |
| 品牌调性 | 4/10 | 主色 #ff5000 橙（淘宝/速卖通同款），logo 是「H」字母块，无品牌故事感 |
| 视觉噪音 | 6/10 | 促销橙红色块连续轰炸：promise 红条 → ticker 橙条 → welcome 橙条 → deal 橙块 → 弹窗橙渐变，全站每处都在喊促销 |
| 内容质感 | 5/10 | **商品图质量是最大变量**：1688 原图参差直接决定页面观感；字体单一（系统字体栈，品牌字体只在活动页用） |

### 6.2 三个真实问题（按 ROI 排序）
1. **商品图规范缺失（最高 ROI）**：card 图 1:1 cover 白底，1688 图什么质量就显示什么。你有图片翻译管线（百炼）和阿里表，应顺手做**图片质检/重抠白底**；placeholder 也要重画（当前是通用 SVG，缺图即丑）。
2. **促销视觉过载（中 ROI）**：hero、ticker、welcome、deal、弹窗全是橙红渐变。建议收敛：首页主视觉（hero）和活动条（ticker）二选一做主角，另一处改中性色；promise 红条（#ff0036 满版红）改浅色提示条。消费者在"每处都打折"里反而对"真便宜"脱敏。
3. **品牌层空白（低 ROI，可后置）**：品牌色板/字体/logo。campaign.css 里已经用了 Fraunces/Lilita One 这类强品牌字体——说明作者会做，只是没铺开。把品牌字体铺到 hero/标题即可明显提质感。

### 6.3 不动清单
- 布局结构（mall 类目飞层、pdp 双栏、购物车网格）完成度高，重构是负 ROI。
- 移动端交互（sheet/弹层）已经是标准电商范式，不动。

## 7. 落地优先级（本周 → 本月）

**本周（用户已锁定两件事）**：
1. **把支付接通（连连，P0-A1）**：配 LIANLIAN_MERCHANT_ID / SUB / PRIVATE_KEY / PUBLIC_KEY / ENV / COUNTRY，验证订单能到 paid。这是所有运营动作的前提——现在未配密钥走 MemoryStripe，订单永远 pending、到不了 paid。
2. **pending 超时释放库存（B1）**：下单即扣库存、无超时机制，未付单永久占库存；加超时任务（Linux cron/systemd）调 cancel_order。
3. 倍率**不改**：代码默认 sale_rate=1.1，线上若已存其他值以线上为准，只读确认现值即可，不做改价。
4. **$1.99 不当主锚**（运费逻辑见 §2）；选品参考用 $6-10 / $15-30。
5. 链接自带参数 + 表格记录渠道来源；B5 渠道追踪等投流前再做。

**本月（代码，按 V2 顺序）**：
1. P0-A：连连密钥、SMTP/域名、线上 DB 快照（三件事不改代码但卡所有进度）。
2. P0-B：B1 pending 释放（本周）；**B5 渠道追踪暂缓**，投流启动前再做。
3. P1：差 X 送券弹窗（P1-1）→ 邮件三连（P1-3）→ 全局进度条（P1-2）。

**下季度（产品决策）**：
- 多人拼团（B 型）要不要立项，取决于 4-6 周凑单率数据。
- UI 改造**暂不动**（用户裁定）：商品图参差是选品/运营层面的事，改橙色和字体又回到改首页，先放一放。

## 8. 周度运营节奏（建议 SOP）

| 周几 | 动作 |
|---|---|
| 周一 | 复盘：/admin/stats 漏斗 + 凑单率 + 客单；定本周目标 |
| 周二 | 选品/组合：换秒杀品、调 bundle 组合、补款品配对 |
| 周三 | 内容：短视频脚本产出（站外），挂 UTM 落地 |
| 周四 | 加热小额投放（预算 <$50），只投已验证的引流品 |
| 周五 | 活动配置：新人/秒杀轮换、券面额微调 |
| 周六日 | 观察自然流 + 复购邮件效果，收集问题 |

**核心指标（每周盯死）**：凑单率（≥60% 生死线）、平均客单（≥$25 目标）、CAC（按渠道）、复购率、首单 CVR。
